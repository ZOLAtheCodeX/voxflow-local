# Clipboard and stored-data privacy: design spec

Spec 3 of the post-v0.1.4 queue. Source: GitHub issue #17 ("Preserve all
clipboard representations during temporary dictation paste"), widened during
brainstorming on 2026-10-30 by findings verified against the code. Decisions
taken by the user: scope is the clipboard plus cockpit session retention;
the clipboard bridge is removed; sessions are deleted on finish with a 7-day
launch sweep; approach A (an ownership object behind a fakeable seam) over a
fix in place (B) and synthetic Unicode typing (C).

## Measured facts driving this work

- `AccessibilityInsertService.simulatePaste` (`AccessibilityInsertService.swift:294-345`)
  saves only `pasteboard.string(forType: .string)` before writing the dictated
  text, and restores only that string. Image-only content is lost, RTF and
  file references collapse to plain text where a string exists, and an empty
  clipboard is left holding the dictated text (issue #17).
- The restore runs in a `defer` after a 300 ms `Task.sleep`. If the insert
  task is cancelled during that sleep, the sleep throws and the `defer`
  restores at once. A target that reads the pasteboard late (Electron) can
  then paste the user's previous clipboard, which may be a password, instead
  of the dictated text.
- The temporary write carries no `org.nspasteboard.TransientType` or
  `org.nspasteboard.AutoGeneratedType` marker and does not use
  `NSPasteboard.ContentsOptions.currentHostOnly`. Clipboard managers that
  follow the nspasteboard.org convention therefore record every pasted
  dictation, and Universal Clipboard offers it to the user's other devices.
- `TextInsertionCoordinator` copies the dictated text to the clipboard after
  every successful insert whose method is not `.simulatedPaste`
  (`TextInsertionCoordinator.swift:101-104` and `:170-173`), the "clipboard
  bridge" from commit `59001f3` (February 2026). Most dictations into native
  apps go through AX-direct insertion, so they permanently replace whatever the
  user had copied. The paste path restores the clipboard, so behaviour already
  differs between the two paths.
- `swift test` writes to the developer's real clipboard in two ways:
  - The `TextInsertionCoordinatorTests` fake defaults to an
    `.accessibilityDirect` success, which trips the bridge.
  - `CockpitCoordinatorTests.test_insert_failure_keeps_cockpit_open_and_session_intact`
    constructs the coordinator with the default `copyFailedInsertion` closure,
    which writes the transcript to `NSPasteboard.general`.

  The spec 2 plan worked around the first by returning `.simulatedPaste` from
  its fake.
- Cockpit sessions are written to `~/Library/Application Support/VoxFlow/sessions/<uuid>.json`
  (every ~5 s while recording, on stop, on undo and on smart actions) and are
  never deleted. `LongFormSessionService.recoverLatestSession()` has no
  production caller, so nothing ever reads these files back. The user's
  machine holds 11 such files (2026-10-27 to 2026-10-30, about 44 KB of full
  transcripts).
- `LongFormSessionService.reset()` is the single point where a session ends
  on purpose: ⌘↩ insert success, Notion append success, the voice "cancel"
  command, and a failed capture start. After `reset()` the autosave loop
  cannot recreate the file, because `save()` returns early when
  `currentSession` is nil.
- The other stored surfaces are already bounded: `insertions.jsonl` rotates at
  ~1 MB with one backup (text retention configurable through
  `VoxFlow.auditTextRetention`), and the rejected-audio ring keeps 8 clips.
  The backend's `AuditLogger` records lengths, never content.
- CI runs `swift test` on a `macos-26` GitHub runner.

## Goals

1. A temporary paste restores the user's clipboard exactly: every item, every
   representation, and the empty state, while the clipboard still holds our
   text. A newer copy by the user always wins.
2. The dictated text placed for a temporary paste is not recorded by
   convention-following clipboard managers and is not offered to Universal
   Clipboard.
3. Cancelling an insert never restores the clipboard before the target has had
   its full window to read the dictated text.
4. A successful insert, by either method, leaves the user's clipboard as it
   was. Deliberate copies (failure recovery, Copy buttons, templates) are
   unchanged.
5. Automated tests never read or write the user's clipboard.
6. A cockpit session's transcript is removed from disk once the session ends
   on purpose, and orphaned session files do not outlive 7 days.

## Non-goals

- A "resume last session" offer at launch. `recoverLatestSession()` stays
  unwired; this is a follow-up.
- A Settings picker for `VoxFlow.auditTextRetention`, and an age limit on the
  rejected-audio ring. Both surfaces are already bounded.
- The view-level Copy buttons (palette Recent tab, assistant handoff card)
  and cockpit ⌘C. They are user-initiated deliberate copies and no test drives
  them.
- Replacing the paste fallback with synthetic Unicode typing (approach C):
  a newline in a terminal runs the line, editors auto-close brackets, and
  long text is slow.
- A size cap on the clipboard snapshot. A cap would have to choose between
  failing the insert and losing the user's clipboard; size and duration are
  logged instead.
- Clipboard managers that ignore the nspasteboard.org markers. They will
  still record the temporary text; nothing in the pasteboard API prevents it.

## Decisions

### 1. A fakeable pasteboard boundary

New file `Sources/VoxFlowApp/Services/PasteboardAccess.swift`:

```swift
/// Every item on a pasteboard, each as its representations in the order
/// the owner offered them. An empty `items` array is the empty clipboard.
struct PasteboardSnapshot: Equatable, Sendable {
    struct Representation: Equatable, Sendable { let type: String; let data: Data }
    struct Item: Equatable, Sendable { let representations: [Representation] }
    let items: [Item]
    static let empty = PasteboardSnapshot(items: [])
    var byteCount: Int { items.reduce(0) { $0 + $1.representations.reduce(0) { $0 + $1.data.count } } }
}

@MainActor
protocol PasteboardAccess: AnyObject {
    var changeCount: Int { get }
    func snapshot() -> PasteboardSnapshot
    /// Replace the contents with `text` as this host's transient,
    /// auto-generated content. Returns the change count after the write,
    /// or nil when the write failed.
    func writeTemporary(_ text: String) -> Int?
    /// Replace the contents with exactly `snapshot`'s items and types.
    func restore(_ snapshot: PasteboardSnapshot)
}
```

`SystemPasteboard: PasteboardAccess` wraps one `NSPasteboard`
(`init(_ pasteboard: NSPasteboard = .general)`):

- `snapshot()` reads `pasteboardItems`, and for each item every type in
  `item.types` order with `data(forType:)`. Types that return nil are skipped;
  items with no readable data are dropped.
- `writeTemporary(_:)` calls `prepareForNewContents(with: .currentHostOnly)`,
  then writes one `NSPasteboardItem` carrying the string under `.string` and
  empty data under `org.nspasteboard.TransientType` and
  `org.nspasteboard.AutoGeneratedType`. Returns `changeCount` on success.
- `restore(_:)` calls `clearContents()`; for a non-empty snapshot it writes one
  `NSPasteboardItem` per snapshot item with `setData(_:forType:)` for each
  representation. No markers are added: the restored content is exactly the
  user's.

The same file holds `enum SystemClipboard` with one
`@MainActor static func copy(_ text: String)` (clear plus a plain
`.string` write), the production writer for deliberate copies (decision 4).

### 2. `TemporaryPasteboard` owns the temporary paste

New file `Sources/VoxFlowApp/Services/TemporaryPasteboard.swift`, a
`@MainActor final class`:

```swift
init(pasteboard: PasteboardAccess = SystemPasteboard(),
     restoreDelay: Duration = TemporaryPasteboard.consumeDelay,
     sleep: @escaping (Duration) async throws -> Void = { try await Task.sleep(for: $0) })

static let consumeDelay: Duration = .milliseconds(300)

struct Lease  // opaque: an id plus the change count after our write
func place(_ text: String) -> Lease?
func stillOwns(_ lease: Lease) -> Bool
func release(_ lease: Lease, dispatched: Bool)
func restorePendingNow()
```

It keeps at most one ownership record: the original snapshot, the change
count after our write, the lease id, and the pending restore task if any.

- **`place`.** If an ownership record exists and `changeCount` still equals
  its owned count, the clipboard still holds our previous dictation: the new
  lease inherits that record's original snapshot and cancels its pending
  restore. Otherwise it takes a fresh `snapshot()`. It then calls
  `writeTemporary`. On success it records the new ownership and returns the
  lease. On failure it restores the original at once, clears the record and
  returns nil. Snapshot item count, byte count and duration are logged
  (`Logger` category `TemporaryPasteboard`); content never is.
- **`stillOwns`** is true when the lease is the current record and
  `changeCount` equals its owned count.
- **`release(dispatched: true)`** schedules the restore in its own `Task`:
  sleep `restoreDelay`, then restore if still owned. The task is not a child
  of the inserting task, so cancelling the insert does not shorten the
  window (goal 3).
- **`release(dispatched: false)`** restores at once if still owned.
- A release for a lease that is no longer the current record does nothing
  (a newer lease superseded it).
- **"Restore if still owned"** compares `changeCount` with the owned count.
  On a match it calls `restore(original)`; on a mismatch the user copied
  something newer and nothing is written. Either way the record is cleared.
- **`restorePendingNow()`** cancels any pending task, restores if still owned,
  and clears the record. `AppDelegate.applicationWillTerminate` calls it
  through a new `AppCoordinator.restoreTemporaryClipboard()` (before
  `shutdownBackend()`), so quitting never leaves dictated text on the
  clipboard.

`AccessibilityInsertService` owns the single `TemporaryPasteboard`, injected
through `init(temporaryPasteboard: TemporaryPasteboard = TemporaryPasteboard())`,
and exposes `restorePendingClipboard()`, which
`AppCoordinator.restoreTemporaryClipboard()` forwards to. (`AppCoordinator`
holds exactly one `AccessibilityInsertService`, so there is one owner.)

### 3. The paste flow in `AccessibilityInsertService.simulatePaste`

1. `guard let lease = temporaryPasteboard.place(text) else { return (false, nil) }`
   replaces the string save, write and `defer`.
2. The activation wait (100 ms if the target was inactive, else 30 ms) and the
   existing cancellation, activity, permission and focus-identity checks stay.
   Each early return calls `release(lease, dispatched: false)` first.
3. New check before Cmd+V: `temporaryPasteboard.stillOwns(lease)`. If false,
   the user copied something during the activation wait (or a newer paste
   superseded this one); release undispatched and return `(false, nil)`.
   Pasting would put content into the target that the receipt would then
   claim was the dictation.
4. Post Cmd+V, then `release(lease, dispatched: true)`.
5. If `policy.submits`, wait `TemporaryPasteboard.consumeDelay` with
   cooperative `Task.sleep` before returning, so Return still follows a
   consumed paste. Cancellation during the wait returns early and
   `maySubmit` skips Enter, as today. Otherwise return at once.

Unchanged: `pasteOutcome` (secure input stays `SECURE_INPUT_BLOCKED`, never
success), `maySubmit`, smart spacing and the prior-insertion record, and the
AX-direct path. Paste inserts now return about 300 ms sooner, visible as a
lower `insert_ms` in receipts.

Under secure input the target never receives Cmd+V; the coordinator's
recovery copy then moves `changeCount`, so the pending restore finds the
clipboard no longer ours and leaves the recovery copy in place, as today.

### 4. `TextInsertionCoordinator`: no bridge, one required clipboard writer

- Delete both bridge blocks (`if result.method != .simulatedPaste { … }`).
  A successful insert writes nothing to the clipboard.
- Replace `copyFailedInsertion: @escaping (String) -> Void = { … }` with
  `copyToClipboard: @escaping @MainActor (String) -> Void` and **no default**
  (main-actor isolated so `SystemClipboard.copy` passes under Swift 6 strict
  concurrency). Every
  deliberate copy goes through it:
  - the auto-insert failure copy
  - the review-insert failure copy (via `copyCurrentText()`)
  - `copyCurrentText()`
  - `copyMeetingMarkdownTemplate()`
  - `copyMeetingNotionTemplate()`
- `AppCoordinator` passes `SystemClipboard.copy`. Each test construction passes
  a recorder, so omitting the argument is a compile error rather than a write
  to the user's clipboard.
- Deliberate copies stay plain clipboard content with no transient markers:
  the user asked for them, so clipboard history recording them is correct.

### 5. Cockpit session retention in `LongFormSessionService`

- `reset()` captures the current session id before clearing it and removes
  `<autoSaveDirectory>/<id>.json`. A missing file (a session reset before
  its first save) is not an error.
- `init` gains `orphanRetention: TimeInterval = LongFormSessionService.orphanRetention`
  (`static let orphanRetention: TimeInterval = 7 * 24 * 60 * 60`). After
  creating the directory, it sweeps every file whose extension is `json` and
  whose base name parses as a `UUID`, removing those whose content
  modification date is earlier than `clock.currentTime() - orphanRetention`.
  It does not decode files, so corrupt ones age out too. Other files in the
  directory are never touched.
- Removal uses `FileManager.removeItem`, not the Trash: a Trash copy would keep
  the plaintext this change exists to remove.
- Failures are logged through the service's `Logger` and never throw or block.
- A session still in review when the app quits stays on disk. That orphan,
  kept for up to 7 days, is the manual recovery window.
- First launch after install on the user's machine: no file is older than
  7 days, so nothing is deleted; the 11 current files age out between about
  2026-11-03 and 2026-11-06.

## Error handling

| Situation | Behaviour |
|---|---|
| `writeTemporary` fails | Original restored at once; `simulatePaste` returns not posted; coordinator recovery copy. |
| Activation fails, cancelled, permission revoked or focus changed before Cmd+V | Undispatched release restores at once; result `INSERT_FAILED` / `CANCELLED` paths as today. |
| User copies before Cmd+V | Paste withheld; undispatched release leaves the user's copy; `INSERT_FAILED`, then the coordinator's recovery copy (accepted edge: it replaces the just-made copy). |
| User copies after Cmd+V | Pending restore finds a newer change count and writes nothing. |
| Second paste before the first restore | Second lease inherits the original; one restore at the end. |
| Insert cancelled after Cmd+V | Restore still waits the full delay. |
| Secure input active | Unchanged honest failure; the recovery copy wins over the pending restore. |
| App quits with a restore pending | `restorePendingNow()` restores immediately. |
| Session file missing at `reset()` | Ignored. |
| Session folder missing or unreadable at sweep | Logged; sweep skipped. |

## Testing

All deterministic; no real timing, no `Thread.sleep`.

**`TemporaryPasteboardTests`.** An in-memory `FakePasteboard: PasteboardAccess`
increments `changeCount` on every write, and the test can simulate a user copy.
A manual sleeper suspends until the test resumes it.
1. Dispatched paste: the text is written; the original is restored only after
   the sleeper is resumed.
2. Undispatched release: restored immediately.
3. Cancelling the inserting task after dispatch does not restore before the
   sleeper resumes.
4. User copy after dispatch: no restore; the user's content remains.
5. User copy before dispatch: `stillOwns` is false.
6. Chained `place` before the first restore: the second lease's restore writes
   the original snapshot. Text #1 is never written back.
7. Release of a superseded lease is a no-op.
8. Empty original: the clipboard is empty after restore.
9. `writeTemporary` failure: the original is restored and `place` returns nil.
10. `restorePendingNow()` restores without the sleeper resuming.

**`SystemPasteboardTests`** run against `NSPasteboard.withUniqueName()` (never
`.general`, released in `tearDown`). This is the one deliberate use of a real
pasteboard, because only a real one proves that representations survive.
- A snapshot and restore round trip is equal for multiple items, PNG data,
  RTF plus string, a file URL, and the empty clipboard.
- `writeTemporary` leaves a string plus both marker types.
- If the runner has no pasteboard server (a write-then-read probe fails), the
  class skips with `XCTSkip` and a message instead of failing.

**`TextInsertionCoordinatorTests` and `CockpitCoordinatorTests`.**
- A successful `.accessibilityDirect` insert never calls the writer.
- A failed auto-insert and a failed review insert each copy exactly once
  through the recorder.
- Every construction site passes a recorder, including the cockpit
  insert-failure test.

**`LongFormSessionServiceTests`.**
- `reset()` after a save deletes the file.
- `reset()` before any save does not throw or log an error.
- The sweep removes a UUID-named JSON file older than the retention (date set
  with `FileManager.setAttributes`), keeps a fresh one, and keeps a non-UUID
  file and a non-JSON file of any age.
- `init` with an unwritable folder still constructs.

**Suites:** `swift test` and `./.venv/bin/python -m pytest backend/tests` green.
There are no backend changes.

## Acceptance criteria

1. Every test above passes locally, and both suites are green.
2. The PR's CI is green; the `SystemPasteboardTests` class either runs or
   skips with its message (recorded in the PR).
3. `grep -n "NSPasteboard" Sources/VoxFlowApp/Services/TextInsertionCoordinator.swift Sources/VoxFlowApp/Services/AccessibilityInsertService.swift`
   returns nothing.
4. Manual, on the installed app (install only with the user's approval):
   1. Copy an image, then dictate into Terminal (the paste path). The image
      is still on the clipboard.
   2. Copy text, then dictate into TextEdit (the direct path). The clipboard
      still holds that text.
   3. Cockpit ⌘↩ into an Electron app inserts the full transcript.
   4. Where a clipboard manager is installed, the dictated text is absent
      from its history.

## Risks and counter-arguments

- **The cockpit closes sooner after Cmd+V.** ⌘↩ now closes the cockpit right
  after posting Cmd+V instead of 300 ms later. Cmd+V is already queued to the
  frontmost target and VoxFlow is not frontmost, so no effect is expected
  (confidence about 80%). Acceptance check 4.3 covers it. The fallback is to
  keep the inline wait for every paste, giving up the latency win.
- **Snapshotting forces promised data.** A large selection in a source app
  means a memory spike and main-thread time before the paste, and a hung
  source app can stall it. Tools that paste and restore accept the same
  trade-off. The log line makes it observable.
- **Removing the bridge removes a convenience.** Pasting a dictation a second
  time from the clipboard after an AX-direct insert no longer works. It never
  worked on the paste path, and the Copy buttons remain.
- **The 7-day sweep can delete a crash orphan the user still wanted.** That
  is the agreed trade-off against keeping transcripts forever. A resume offer
  is the follow-up that makes orphans visible.
