# Clipboard and stored-data privacy implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A temporary dictation paste restores the user's clipboard exactly and
hides the dictated text from clipboard history and Universal Clipboard. A
successful insert no longer overwrites the clipboard, tests never touch it, and
cockpit session transcripts are deleted on finish, with orphans swept after
7 days.

**Architecture:** A thin `PasteboardAccess` seam wraps `NSPasteboard`. A
`@MainActor` `TemporaryPasteboard` owns the snapshot, write and restore cycle
through leases checked by `changeCount`, with a deferred restore that
cancellation cannot shorten. `AccessibilityInsertService` delegates to it.
`TextInsertionCoordinator` loses the clipboard bridge and takes a required
clipboard writer. `LongFormSessionService` deletes on `reset()` and sweeps at
init.

**Tech Stack:** Swift 6.2 (strict concurrency), AppKit `NSPasteboard`, XCTest,
SwiftPM.

**Spec:** `docs/superpowers/specs/2026-10-30-clipboard-and-stored-data-privacy-design.md`

## Global Constraints

- Swift 6.2 strict concurrency, macOS 14+ deployment target; the build must stay free of new concurrency errors.
- Tests never touch `NSPasteboard.general`, `~/Library/Application Support/VoxFlow`, `~/Library/Logs/VoxFlow`, or port 8765. Real pasteboard tests use `NSPasteboard.withUniqueName()` only, released in a teardown block.
- Waits use cooperative `Task.sleep`; never `Thread.sleep`.
- `AccessibilityInsertService.pasteOutcome` and `maySubmit` keep their current signatures and behaviour (secure input stays `SECURE_INPUT_BLOCKED`).
- Every existing `Task.isCancelled` / `Task.checkCancellation()` gate in the insert paths stays.
- Restore delay: `TemporaryPasteboard.consumeDelay = .milliseconds(300)`.
- Marker types, exact strings: `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType`.
- The temporary write uses `prepareForNewContents(with: .currentHostOnly)`; restore adds no markers.
- Session orphan retention: `LongFormSessionService.orphanRetention = 7 * 24 * 60 * 60` seconds; deletion uses `FileManager.removeItem`, never the Trash.
- Logging through `os.Logger` (subsystem `local.voxflow.app`); never `print`. Never log clipboard content.
- New prose (comments, docs, commit messages) uses no em dashes. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `NSPasteboard.changeCount` advances on `clearContents()` / `prepareForNewContents(with:)`, not on `writeObjects` (verified by probe). The fake models this.

## Review Focus

1. A clipboard item with a lazily provided type whose provider supplies nothing: the snapshot skips that type without hanging, and the item's other types still round trip. Test: Task 1, `test_snapshot_skips_types_whose_provider_supplies_nothing`.
2. Password-manager content marked `org.nspasteboard.ConcealedType`: the marker survives restore, so clipboard managers keep hiding it. Test: Task 1, `test_restore_keeps_concealed_marker`.
3. Multi-line dictation with emoji and combining characters: the temporary write reads back byte-identical. Test: Task 1, `test_write_temporary_preserves_multiline_and_emoji_text`.
4. A second paste after the first restore has already completed, with a user copy in between: the second paste snapshots the user's newer copy, not the stale original. Test: Task 2, `test_paste_after_completed_restore_snapshots_current_clipboard`.
5. A multi-megabyte clipboard (a copied image): the round trip is exact. Test: Task 1, `test_large_payload_round_trips`.

- [ ] **Step 4: Implement `TemporaryPasteboard.swift`** per spec decision 2.
  - **State:** one optional private ownership record holding `original: PasteboardSnapshot`, `ownedChangeCount: Int`, `leaseID: UInt64` and `restoreTask: Task<Void, Never>?`. `Lease` carries `id` and `ownedChangeCount`, and ids come from an incrementing counter.
  - **`place`:** inherit `original` when a record exists and `changeCount == record.ownedChangeCount`; otherwise take `snapshot()`. Cancel any old `restoreTask`. Then `writeTemporary`.
    - On nil, call `pasteboard.restore(original)` unconditionally (the write already cleared the clipboard), clear the record and return nil.
    - On success, store the new record and log item count, byte count and snapshot milliseconds at `.info` (no content).
  - **`stillOwns`:** the record's `leaseID == lease.id` and `changeCount == record.ownedChangeCount`.
  - **`release`:** ignore unless `record?.leaseID == lease.id`.
    - Undispatched: call `restoreIfOwned(leaseID: lease.id)` now.
    - Dispatched: store `Task { @MainActor [weak self] in try? await self?.sleep(delay); guard !Task.isCancelled else { return }; self?.restoreIfOwned(leaseID: id) }` in the record.
  - **`private func restoreIfOwned(leaseID: UInt64)`:** a no-op unless the record's `leaseID` matches. On a match, restore `original` only when `changeCount == ownedChangeCount`, then clear the record either way.
  - **`restorePendingNow`:** cancel the record's `restoreTask` and call `restoreIfOwned(leaseID:)` with the record's own id.
  - Doc comment on the class: why the restore task is not a child of the inserting task (finding 4 in the spec).
